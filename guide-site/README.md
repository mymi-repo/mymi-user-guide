# MYMI 유저가이드 (Docusaurus)

Docusaurus 3.10 기반 정적 사이트. `MYMI_user_guide/` (GitBook)로부터 마이그레이션됨.

## 핵심 셋업

- **베이스 URL**: `/guide/` — 메인 도메인 `mymi.live` 하위 경로
- **로케일**: `ko`, `en`, `ja`, `zh-TW` — 한국어 기본, 상단 언어 선택 메뉴 제공
- **폰트**: 한국어·영어 Pretendard, 일본어 Pretendard JP(jsDelivr CDN), 번체중국어 운영체제의 번체 글꼴
- **검색**: 추후 Algolia DocSearch 또는 로컬 검색 플러그인
- **컬러**: 서비스 화면과 같은 purple(#9333ea, 다크 모드 #c084fc)·zinc 보조색·다크 배경 #151516
- **디자인·용어**: 아래 [디자인 요소](#디자인-요소), 화면 이름과 번역 용어는 [용어집](용어집.md)

## 로컬 개발

### 모든 언어를 확인하는 미리보기

가이드 검토와 언어 전환을 함께 확인할 때는 다음 명령을 사용한다. 전체 언어를 빌드한 뒤 3001번 포트에서 제공한다.

```bash
cd guide-site
npm install
npm run preview
```

→ `http://localhost:3001/guide/` 에서 상단 메뉴로 한국어·영어·일본어·번체중국어를 전환한다. 같은 포트에서 `start`가 실행 중이라면 먼저 종료한다.

미리보기는 빌드 결과를 제공한다. 문서를 수정한 뒤 다른 터미널에서 `npm run build`를 실행하고 브라우저를 새로고침하면 반영된다.

### 한 언어를 편집하는 개발 서버

```bash
cd guide-site
npm install
npm run start
```

→ `http://localhost:3000/guide/` 에서 라이브 미리보기.

FE 개발 서버와 함께 사용할 때는 포트를 지정한다. Windows PowerShell에서는 `npm` 대신 `npm.cmd`를 사용할 수 있다.

```bash
npm run start -- --port 3003 --locale ko
```

→ `http://localhost:3003/guide/`

개발 서버는 한 번에 한 언어만 제공하므로 언어 선택 메뉴를 표시하지 않는다. 영어 본문을 편집할 때는 `npm run start -- --port 3004 --locale en`으로 별도 실행한다. 모든 언어를 한 사이트에서 전환하려면 위의 `npm run preview`를 이용한다.

`npm run start`, `npm run build`, `npm run preview`는 `scripts/run-docusaurus.mjs`를 통해 실행한다. 언어별 개발 캐시(`.docusaurus/dev-ko` 등)와 빌드 캐시(`.docusaurus/build`)를 분리하므로 개발 서버를 켜 둔 상태에서 전체 언어를 빌드해도 화면이 다른 언어로 바뀌지 않는다. `npx docusaurus start/build`로 직접 실행하면 이 분리를 거치지 않는다.

## 빌드

```bash
npm run build
npm run serve -- --port 3001   # 이미 빌드한 모든 언어의 결과 확인
```

빌드 결과: `build/` 디렉토리.

빌드 미리보기의 언어별 주소:

| 언어 | 주소 |
| --- | --- |
| 한국어 | `http://localhost:3001/guide/` |
| 영어 | `http://localhost:3001/guide/en/` |
| 일본어 | `http://localhost:3001/guide/ja/` |
| 번체중국어 | `http://localhost:3001/guide/zh-TW/` |

`serve`는 빌드된 파일을 제공하므로 수정 후 다시 빌드해야 한다. 본문을 계속 수정할 때는 `start`를 사용한다.

## 배포

현재는 `MYMI_frontend/scripts/build-guide.mjs`가 이 서브모듈의 가이드를 빌드하고, 결과를 FE의 `public/guide/`로 복사한다. 전체 언어가 함께 빌드된다. 가이드 서브모듈 변경과 FE의 서브모듈 참조 반영을 기존 배포 절차로 진행한다.

가이드만 로컬 확인할 때는 이 디렉터리에서 빌드한다. FE 루트의 빌드를 실행하면 가이드 복사 외에 FE 빌드도 진행된다.

## 콘텐츠 수정

`docs/` 디렉토리의 한국어 마크다운 파일을 직접 수정한다. 로컬 수정과 미리보기만으로 운영 사이트에 배포되지는 않는다.

각 .md 파일 frontmatter:
- `sidebar_position`: 사이드바 순서
- `description`: 메타 description (검색 결과에 표시됨)
- `slug`: URL 경로 (`intro.md`만 `slug: /` 사용해서 루트로 매핑)
- `last_update.date`: 내용을 실제로 수정·검토한 날짜 (`YYYY-MM-DD`)

### 수정일 표시

문서에 `last_update.date`가 있으면 그 날짜를 표시하고, 없으면 해당 파일의 마지막 Git 커밋 날짜를 사용한다. 개발 모드도 실제 Git 기록을 읽으며, Docusaurus의 2018년 예시 날짜와 개발용 안내 문구는 사용하지 않는다. 날짜 형식과 ‘최종 수정’ 문구는 선택한 언어에 맞춰 표시된다.

```yaml
last_update:
  date: 2026-09-22
```

문서를 실제로 고친 날에만 날짜를 갱신한다. 빌드 날짜로 모든 문서를 덮어쓰지 않는다. 새 번역에도 검토 날짜를 기록한다. Git 기록이 없는 빌드에서는 기존 FE 빌드 스크립트가 `DOCUSAURUS_SHOW_LAST_UPDATE=false`를 전달하여 수정일 표시를 끈다.

### 번역 추가

번역 파일은 한국어와 같은 상대 경로에 둔다.

```text
docs/account/sign-up.md
i18n/en/docusaurus-plugin-content-docs/current/account/sign-up.md
i18n/ja/docusaurus-plugin-content-docs/current/account/sign-up.md
i18n/zh-TW/docusaurus-plugin-content-docs/current/account/sign-up.md
```

- `slug`, 문서 경로, `sidebar_position`은 언어 간에 유지한다.
- 번역 문서에서 다른 문서를 연결할 때는 `(/account/persona.md)`처럼 문서 루트 기준 Markdown 경로를 쓴다. 번역 파일이 있으면 해당 언어로, 없으면 한국어 원문으로 연결된다. `../account/persona.md` 같은 상대 경로는 미번역 문서를 찾지 못할 수 있다.
- 본문·제목·`description`을 번역하되, 버튼 이름과 로그인 수단은 서비스의 해당 언어 화면을 확인한다. 화면 이름과 용어는 [용어집](용어집.md)을 따른다.
- 수정일과 번역 대기 안내는 `i18n/<locale>/code.json`, 상단·하단 메뉴는 `docusaurus-theme-classic/*.json`, 사이드바 카테고리는 `docusaurus-plugin-content-docs/current.json`에서 관리한다.
- 사이트 제목·소개·검색 키워드는 `docusaurus.config.js`의 `siteTexts`에서 관리한다.
- 번역 파일이 없는 문서는 한국어 원문으로 표시되며, 본문 위에 해당 언어로 번역 대기 안내가 나타난다. 한국어 원문을 번역 폴더에 복사하여 번역 완료로 취급하지 않는다.

#### 언어판마다 그 나라 이야기만 쓴다

언어판은 한국어판의 번역이 아니라 그 나라 이용자를 위한 문서다. 한국어판에 일본·대만·미국 계정의 절차를 쓰지 않고, 세 언어판에 한국 계정의 절차를 쓰지 않는다. 다른 나라 절차를 참고용으로 덧붙이지도 않는다.

계정의 나라는 가입할 때 표시 언어로 정해지고 바뀌지 않는다. 그래서 언어판과 나라가 하나씩 맞물린다. 번역할 때는 한국어 문장을 옮기지 말고 아래 표의 그 나라 값으로 다시 쓴다.

- 결제·환불 문서는 번역하지 않고 나라별로 새로 쓴다. 통화, 결제 수단, 가격, 첫 구매 상품, 구매 조건이 모두 다르다.
- 번역 파일이 없는 문서는 세 언어판에도 한국어 원문이 그대로 보인다. 한국 전용 내용이 있는 문서는 번역 전까지 그 상태가 된다는 점을 배포 판단에 넣는다. 2026-10-03부터 모든 문서가 세 언어로 번역돼 있다. 새 문서를 한국어로만 더하면 세 언어판에는 번역 대기 안내와 함께 한국어가 보인다.

- 카드 제목은 연결한 문서의 제목과 같게 쓴다. 문서 제목을 바꾸면 첫 화면 카드도 같이 고친다.
- 화면 캡처는 `static/img/screens/<locale>/`에 WebP로 두고 각 언어의 화면을 쓴다. `alt`는 비워 두지 않는다. 실제 계정의 닉네임·아이디·잔액·채팅방 ID는 담지 않는다.
- 페이지 끝은 **자주 막히는 곳**(`<details>`)과 **다음에 할 일**(`CardGrid`) 순서로 맺는다. 제작 가이드의 본문은 해요체로 쓴다.
- 문서 본문에서 `{{user}}`, `{{char}}`, `{{URL}}`처럼 중괄호가 들어간 글은 반드시 `` ` `` 로 감싼다. MDX가 중괄호를 코드로 읽어 빌드가 깨진다.

### 제작 가이드의 화면 캡처

제작 가이드의 캡처는 예시 작품 데이터를 넣은 개발 환경에서 찍는다. 실제 계정·작품을 쓰지 않는다. 찍는 방법과 도구는 FE 저장소의 내부 메모 `docs/FE/유저-문서/2026-09-30-가이드-저장소-내부-메모.md`에 있다.

**간편 모드 화면(2026-10-04)**: `mode-card`·`mode-intro`·`mode-locked`·`simple-*` 21장과 전문가 모드 기본 정보 위쪽 `create-overview`·`create-publish-check`·`first-basic-top` 3장은 **네 언어 모두 실제 웹 앱 캡처**다(목업이 아니다). 출시 코드와 같은 커밋을 스크래치 복사본으로 뽑아 개발 서버(3100번)에서 찍었다 — 도구와 방법은 FE 저장소 로컬 `local_scripts/FE/guide-screens-simple/README.md`. 라벨이 QA로 바뀌면 그 도구로 네 언어를 다시 찍는다.

한국어판에서는 `lorebook`·`lorebook-editor`·`legacy-assets`·`manage-menu` 네 장이 캡처가 아니라 목업이다(2026-10-02). 컴포넌트의 Tailwind 클래스와 같은 i18n 문구로 그렸고, 도구와 방법은 같은 내부 메모에 있다. 앱 화면이 바뀌면 목업도 같이 고쳐 다시 그린다.

앱 화면이 바뀌면 같은 이름으로 다시 찍어 덮어쓴다.

**세 언어판(2026-10-03)**: en·ja·zh-TW의 화면 이미지 50장은 목업이다(`static/img/screens/<locale>/`, 위 간편 모드 화면 24장은 제외). 한국어판과 같은 이름·같은 순서로 그렸고, 문구는 각 언어 앱의 i18n에서 그대로 읽는다. 예시 작품의 긴 글은 각 언어 문서의 코드 블록에서 읽어 문서와 목업이 글자까지 같다. 번체 앱은 추천 태그 이름이 한국어로, 검색으로 고른 태그는 영어로 나오는데(`localizeTag`가 번체를 모르고, BE는 번역이 없으면 영어를 준다) 목업도 앱이 보여 주는 그대로 그렸다. 추천 그림체 썸네일 세 장은 서버가 주는 그림이라 한국어 캡처에서 잘라 쓴다. 앱 화면이 바뀌면 목업 도구의 `screens-*.mjs`를 고쳐 세 언어를 다시 그린다.

### 언어별 글꼴

Pretendard(한국어판)에는 한국식 한자·가나 글리프가 들어 있다. 일본어·번체중국어 본문에 먼저 쓰면 한자 모양이 그 언어와 달라진다.
그래서 일본어는 Pretendard JP를 함께 불러 본문에 쓰고(`docusaurus.config.js`의 `fontStylesheets`), 번체중국어는 운영체제의 번체 글꼴을 먼저 쓴다(`custom.css`의 `html[lang]` 규칙). 번역 대기 문서의 한국어 본문은 어느 언어에서든 Pretendard로 보인다.

### 링크 공유 이미지

`static/img/og/og-<locale>.png`(1200×630)를 언어별로 쓴다. 원본은 `og/card.html`이다.

1. 문구를 바꿀 때는 `og/card.html`의 `texts`와 `docusaurus.config.js`의 `siteTexts`를 함께 고친다.
2. Chrome에서 `og/card.html?locale=ko`를 연다.
3. 개발자 도구의 기기 모드에서 크기를 1200×630, 배율을 100%로 맞춘다.
4. 명령 메뉴의 **Capture screenshot**으로 저장하고 `static/img/og/og-ko.png`를 교체한다. 다른 언어는 `locale` 값만 바꿔 반복한다.

### 예시 작품 이미지

가이드 전체에서 한 가지 예시 작품을 쓴다. 설정은 작품 제작 화면의 작품 정보 예시(2031년 봉쇄된 지하 도시 서울)와 같다. 실제 서비스 작품의 이미지는 쓰지 않는다. 이미지는 `static/img/example/`에 있다.

| 파일 | 코드 | 내용 |
| --- | --- | --- |
| `A-base.webp` | A 기본 모습 | 강민우, 지하 도시의 안내인 |
| `A-1.webp`, `A-2.webp`, `A-3.webp` | A/1, A/2, A/3 | 웃음, 슬픔, 분노 |

- 읽는 사람이 그대로 따라 만들 수 있도록 앱의 추천 스타일과 앱의 태그 목록에 있는 태그만으로 만들었다. 생성 조건과 기록은 FE 저장소의 내부 메모 `docs/FE/유저-문서/2026-09-30-가이드-저장소-내부-메모.md`에 있다.

## 사이드바

가이드는 세 영역으로 나뉘고, 상단 메뉴의 **이용 가이드 · 제작 가이드 · 도움말**이 각 사이드바의 첫 문서로 간다.

| 사이드바 | 상단 메뉴 | 문서 폴더 |
| --- | --- | --- |
| `useSidebar` | 이용 가이드 | `getting-started`, `account`, `chatting`, `payment` |
| `createSidebar` | 제작 가이드 | `create/start`(작품 만들기), `create/simple`(간편 모드), `create/making`(전문가 모드), `creator-support` |
| `helpSidebar` | 도움말 | `faq`, `policy` |

- 분류 이름과 순서는 `sidebars.js`에서 정한다. 폴더의 `_category_.json`은 쓰지 않는다. 분류 이름을 바꾸면 각 언어의 `docusaurus-plugin-content-docs/current.json` 키도 바꾼다.
- 분류 안 문서 순서는 각 .md 파일 frontmatter `sidebar_position`.
- 제작 가이드 문서는 `slug`로 주소를 정한다(`/create/simple/first-work`, `/create/first-work`(전문가 모드), `/create/expert/overview` 등). 폴더 이름(`start`·`simple`·`making`)은 주소에 들어가지 않는다. `create/legacy/*`는 예전 주소를 새 안내로 보내는 숨김 문서다.
- 첫 화면(`intro.md`)과 예전 주소 안내용 숨김 문서(`unlisted: true`)는 어느 사이드바에도 넣지 않는다. `character-creation/*`, `creation-guide/*`는 2026-09-29 제작 가이드 개편 때 새 문서로 안내하는 숨김 문서가 됐다.
- 숨김 문서에 기본 테마가 붙이는 "색인되지 않은 문서" 경고 상자는 `src/theme/ContentVisibility/Unlisted`에서 감췄다. 검색 제외 메타 태그(noindex)는 그대로 붙는다.
