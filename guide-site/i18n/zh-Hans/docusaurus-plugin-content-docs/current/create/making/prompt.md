# 撰写提示词

写在**提示词**分页的文字，是 AI 在聊天中每次产生回复时都会原样读取的设置。世界观、登场人物、隐藏设置、进行规则，以及何时使用图片与组件，都写在这里。

:::info
这是专家模式的说明。简易模式没有提示词分页，而是填写基本信息步骤的字段。请见[撰写设置与介绍](/create/simple/write)。
:::

## 两种方式：基本型与自行撰写

<ScreenStep src="/img/screens/zh-Hans/prompt-presets-open.png" alt="提示词预设选项展开的画面" caption="提示词预设">

点击分页最上方的**提示词预设**来选择方式。一开始选的是**自行撰写**。

- **基本型**：填好作品信息、图片代码、组件字段后，由 MYMI 合并。
- **自行撰写**：AI 读取的全部内容由自己撰写，格式不限。

</ScreenStep>

| | 基本型 | 自行撰写 |
| --- | --- | --- |
| 写在哪里 | 作品信息、图片输出规则、例外、组件输出规则字段 | 提示词一个字段 |
| 图片・组件规则 | 只要写代码的含义与出现时机，规则句子会自动加上 | 要自己写输出格式与何时使用 |
| 字数 | 自己写的文字合计 10,000 字。自动加上的标题与代码不计算 | 10,000 字 |
| 适合的人 | 第一次制作的人、会用很多图片的作品 | 已经有明确想法的人 |

:::info[切换方式时]
切换方式后，画面上还是会留着你写的内容。但实际保存的只有**所选方式的文字**。这并不是轮流保存两种方式文字的功能。
:::

## 用基本型撰写

### 作品信息

<ScreenStep src="/img/screens/zh-Hans/first-prompt.png" alt="专家模式填写作品信息与输出规则" caption="基本型 · 作品信息">

在**作品信息**中，用 `####` 小标题分成世界观 → 登场人物 → 隐藏设置 → 进行规则来写。项目写成 `- **项目**: 值`，人物的项目写在名字那一行的下方。

要指称用户时，写 `{{user}}`。字段空白时会显示灰色范例，照着那个样式写就可以。

</ScreenStep>

范例作品的作品信息在[创建第一个作品](/create/first-work#2-撰写提示词)。

### 图片输出规则与例外

<ScreenStep src="/img/screens/zh-Hans/prompt-basic-codes.png" device="part" alt="基本型提示词中的角色、情境、其他代码与例外规则" caption="图片输出规则 · 例外 · 组件输出规则">

在素材分页放入图片并设置代码后，就会出现代码表。为每个代码简短写下**含义**。

- **角色代码**：角色文件夹。写是谁。例：`A` = 姜民宇
- **情境代码**：文件夹内图片的代码。写何时出现。例：`1` = 笑
- **其他代码**：文件夹外的图片。写是什么。例：`BG1` = 检疫所走廊
- **例外**：如果某个人物没有某个情境，就写成 `无 B/3`。

没有含义的代码 AI 无法使用。详情请见[在对话中显示图片](/create/images-in-chat)。

</ScreenStep>

### 组件输出规则

在组件分页添加组件后，这里会出现调用标签。为每个组件写下**何时出现**。例：`战斗开始时与体力变化时。hp = 体力，mp = 魔力。`详情请见[加入组件](/create/components)。

### 组合后的提示词

在分页最下方的**组合后的提示词**确认字段合并后的结果。AI 会原样读取这段文字。制作过程中，还没有图片的代码也可能显示在代码表里，但实际对话只会带入有图片的代码。

## 用自行撰写的方式撰写

<ScreenStep src="/img/screens/zh-Hans/prompt-custom.png" device="part" alt="自定义提示词的直接编辑区域" caption="自行撰写 · 提示词">

所有内容都写在**提示词**这一个字段里。请不要漏掉这三件事。

1. **作品信息**：世界观・登场人物・隐藏设置・进行规则
2. **图片输出规则**：以素材分页的文件夹・代码为准，哪个场面放哪张图
3. **组件输出规则**：何时调用组件分页的标签

字段空白时显示的范例，结构和基本型产生的文字相同，照着写也可以。

</ScreenStep>

:::warning[图片与组件规则要自己写]
在自行撰写中，就算添加了素材与组件，规则句子也不会自动加上。如果没有写在提示词里，AI 就不知道何时该放图片、何时该调用标签。
:::

:::warning[`{{char}}` 不会自动替换]
写在提示词里的 `{{char}}` 不会自动换成人物名称。请直接写出人物名称。用户则写成 `{{user}}`。
:::

<details>
<summary>查看自行撰写的完整范例</summary>

这和作品制作画面中的范例是同一段文字。代码表与组件标签，是配合范例作品的素材和组件写的。

```md
### 作品信息
#### 世界观
- **背景**: 2031 年，被封锁的地下城市首尔。地表已受污染而遭弃置。
- **开场**: {{user}}失去记忆，在检疫所醒来。

#### 登场人物
**姜民宇**
- **角色**: 地下城市的引路人，32 岁
- **性格**: 悠哉，爱开玩笑
- **语气**: 不用敬语，句尾拖长
- **关系**: 知道{{user}}的真实身分，却装作不知道

**李书妍**
- **角色**: 检疫所医师，28 岁
- **性格**: 公事公办、冷静
- **语气**: 简短的敬语
- **关系**: 怀疑{{user}}的失忆并非意外

#### 隐藏设置
- 民宇接到监视{{user}}的命令，不会主动向用户透露。
- {{user}}的记忆是管理局抹除的。

#### 进行规则
- 第一次对话时，民宇带{{user}}走出检疫所。
- 当{{user}}试图找回记忆时，书妍会一次给一条线索。

### 图片输出规则
从下方代码表中选出场景里实际登场的人物・背景，以图片呈现。每次回应至少一张 — 把场景中心人物的图片单独放在该人物第一句对话或动作的正前方一行，焦点转到其他人物时，另起一行放入该人物的图片。表情・情境改变时，更换情境代码。
格式: `![]({{URL}}/角色代码/情境代码.webp)`，其他代码为 `![]({{URL}}/其他代码.webp)`。只照原样使用下表中的代码，不要自创表中没有的代码・路径，也不要使用例外中列出的组合。不放入不在场景中的人物的图片。
角色代码:
A=姜民宇
B=李书妍
情境代码:
1=笑
2=悲伤
3=愤怒
其他代码:
BG1=检疫所走廊
例外: 无 B/3
范例: 角色代码 A + 情境代码 1 → `![]({{URL}}/A/1.webp)`

### 组件输出规则
在符合规则的时刻，把下方标签原样以单独一行输出。
- `<StatusWindow hp={value} mp={value} />`: 战斗开始时与体力变化时。hp = 体力，mp = 魔力。
```

</details>

## 写好的诀窍

以下不是 MYMI 保证的规则，而是制作作品时有帮助的方法。完成制作后，请用完成画面的**查看作品**实际聊聊看，一边调整。想在其他用户看到之前先测试，可以把**其他设置**的**公开设置**设为**不公开**再完成制作。

- <strong>把信息和指示分开。</strong>世界观、人物、隐藏设置当作事实来写，进行规则则写成「要做～」这样的行动，就不容易搞混。
- <strong>为每个人物填写相同的项目。</strong>为所有人物写下角色、性格、语气、关系，即使有很多人物登场，语气也不会混在一起。
- <strong>用例子说明语气。</strong>像「不用敬语，句尾拖长」这样点出特征，或是写一句台词当例子。
- <strong>隐藏设置要连同揭露的条件一起写。</strong>例如「不主动向用户透露」、「被问三次以上就坦白」。
- <strong>偶尔才出现的设置移到设定集。</strong>像特定地点、组织这类只有名称出现时才需要的设置，放在[设定集](/create/lorebook)，提示词就会变短。
- <strong>需要对话范例的话，写在作品信息里。</strong>没有另外放范例对话的字段。

## 遇到问题时

<details>
<summary>显示「有角色代码没有说明。」</summary>

基本型的**图片输出规则**中，有代码没有写含义。请把角色代码、情境代码、其他代码的字段都填好。如果是不会用到的图片，就到素材分页删除。

</details>

<details>
<summary>显示「提示词字段的总字数超过10,000字。」</summary>

基本型会把作品信息、代码含义、例外、组件规则中写的文字全部加起来计算。不常用到的设置，请试着移到[设定集](/create/lorebook)。

</details>

<details>
<summary>AI 不放图片</summary>

如果是自行撰写，请确认是否已把**图片输出规则**写进提示词。如果是基本型，请确认每个代码都有含义、素材分页的图片都已完成。即使如此，偶尔还是可能漏掉，因为 AI 每次的回复都不一样。

</details>
