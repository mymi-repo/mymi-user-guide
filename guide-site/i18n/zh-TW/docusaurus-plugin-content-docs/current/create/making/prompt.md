# 撰寫提示詞

寫在**提示詞**分頁的文字，是 AI 在聊天中每次產生回覆時都會原樣讀取的設定。世界觀、登場人物、隱藏設定、進行規則，以及何時使用圖片與元件，都寫在這裡。

:::info
這是專家模式的說明。簡易模式沒有提示詞分頁，而是填寫基本資訊步驟的欄位。請見[撰寫設定與介紹](/create/simple/write)。
:::

## 兩種方式：基本型與自行撰寫

<ScreenStep src="/img/screens/zh-TW/prompt-presets-open.webp" alt="提示詞預設清單。有自行撰寫與基本型兩種" caption="提示詞預設">

點選分頁最上方的**提示詞預設**來選擇方式。一開始選的是**自行撰寫**。

- **基本型**：填好作品資訊・圖片代碼・元件欄位後，由 MYMI 合併。
- **自行撰寫**：AI 讀取的全部內容由自己撰寫，格式不限。

</ScreenStep>

| | 基本型 | 自行撰寫 |
| --- | --- | --- |
| 寫在哪裡 | 作品資訊、圖片輸出規則、例外、元件輸出規則欄位 | 提示詞一個欄位 |
| 圖片・元件規則 | 只要寫代碼的含義與出現時機，規則句子會自動加上 | 要自己寫輸出格式與何時使用 |
| 字數 | 自己寫的文字合計 10,000 字。自動加上的標題與代碼不計算 | 10,000 字 |
| 適合的人 | 第一次製作的人、會用很多圖片的作品 | 已經有明確想法的人 |

:::info[切換方式時]
切換方式後，畫面上還是會留著你寫的內容。但實際儲存的只有**所選方式的文字**。這並不是輪流保存兩種方式文字的功能。
:::

## 用基本型撰寫

### 作品資訊

<ScreenStep src="/img/screens/zh-TW/first-prompt.webp" alt="基本型的作品資訊欄寫下世界觀與登場人物的畫面" caption="基本型 · 作品資訊">

在**作品資訊**中，用 `####` 小標題分成世界觀 → 登場人物 → 隱藏設定 → 進行規則來寫。項目寫成 `- **項目**: 值`，人物的項目寫在名字那一行的下方。

要指稱使用者時，寫 `{{user}}`。欄位空白時會顯示灰色範例，照著那個樣式寫就可以。

</ScreenStep>

範例作品的作品資訊在[建立第一個作品](/create/first-work#2-撰寫提示詞)。

### 圖片輸出規則與例外

<ScreenStep src="/img/screens/zh-TW/prompt-basic-codes.webp" device="part" alt="圖片輸出規則的角色代碼・情境代碼・其他代碼欄位，以及例外與元件輸出規則" caption="圖片輸出規則 · 例外 · 元件輸出規則">

在素材分頁放入圖片並設定代碼後，就會出現代碼表。為每個代碼簡短寫下**含義**。

- **角色代碼**：角色資料夾。寫是誰。例：`A` = 姜民宇
- **情境代碼**：資料夾內圖片的代碼。寫何時出現。例：`1` = 笑
- **其他代碼**：資料夾外的圖片。寫是什麼。例：`BG1` = 檢疫所走廊
- **例外**：如果某個人物沒有某個情境，就寫成 `無 B/3`。

沒有含義的代碼 AI 無法使用。詳情請見[在對話中顯示圖片](/create/images-in-chat)。

</ScreenStep>

### 元件輸出規則

在元件分頁新增元件後，這裡會出現呼叫標籤。為每個元件寫下**何時出現**。例：`戰鬥開始時與體力變化時。hp = 體力，mp = 魔力。`詳情請見[加入元件](/create/components)。

### 組合後的提示詞

在分頁最下方的**組合後的提示詞**確認欄位合併後的結果。AI 會原樣讀取這段文字。製作過程中，還沒有圖片的代碼也可能顯示在代碼表裡，但實際對話只會帶入有圖片的代碼。

## 用自行撰寫的方式撰寫

<ScreenStep src="/img/screens/zh-TW/prompt-custom.webp" device="part" alt="自行撰寫方式的提示詞欄與說明文字" caption="自行撰寫 · 提示詞">

所有內容都寫在**提示詞**這一個欄位裡。請不要漏掉這三件事。

1. **作品資訊**：世界觀・登場人物・隱藏設定・進行規則
2. **圖片輸出規則**：以素材分頁的資料夾・代碼為準，哪個場面放哪張圖
3. **元件輸出規則**：何時呼叫元件分頁的標籤

欄位空白時顯示的範例，結構和基本型產生的文字相同，照著寫也可以。

</ScreenStep>

:::warning[圖片與元件規則要自己寫]
在自行撰寫中，就算新增了素材與元件，規則句子也不會自動加上。如果沒有寫在提示詞裡，AI 就不知道何時該放圖片、何時該呼叫標籤。
:::

:::warning[`{{char}}` 不會自動替換]
寫在提示詞裡的 `{{char}}` 不會自動換成人物名稱。請直接寫出人物名稱。使用者則寫成 `{{user}}`。
:::

<details>
<summary>查看自行撰寫的完整範例</summary>

這和作品製作畫面中的範例是同一段文字。代碼表與元件標籤，是配合範例作品的素材和元件寫的。

```md
### 作品資訊
#### 世界觀
- **背景**: 2031 年，被封鎖的地下城市首爾。地表已受污染而遭棄置。
- **開場**: {{user}}失去記憶，在檢疫所醒來。

#### 登場人物
**姜民宇**
- **角色**: 地下城市的引路人，32 歲
- **性格**: 悠哉，愛開玩笑
- **語氣**: 不用敬語，句尾拖長
- **關係**: 知道{{user}}的真實身分，卻裝作不知道

**李書妍**
- **角色**: 檢疫所醫師，28 歲
- **性格**: 公事公辦、冷靜
- **語氣**: 簡短的敬語
- **關係**: 懷疑{{user}}的失憶並非意外

#### 隱藏設定
- 民宇接到監視{{user}}的命令，不會主動向使用者透露。
- {{user}}的記憶是管理局抹除的。

#### 進行規則
- 第一次對話時，民宇帶{{user}}走出檢疫所。
- 當{{user}}試圖找回記憶時，書妍會一次給一條線索。

### 圖片輸出規則
從下方代碼表中選出場景裡實際登場的人物・背景，以圖片呈現。每次回應至少一張 — 把場景中心人物的圖片單獨放在該人物第一句對話或動作的正前方一行，焦點轉到其他人物時，另起一行放入該人物的圖片。表情・情境改變時，更換情境代碼。
格式: `![]({{URL}}/角色代碼/情境代碼.webp)`，其他代碼為 `![]({{URL}}/其他代碼.webp)`。只照原樣使用下表中的代碼，不要自創表中沒有的代碼・路徑，也不要使用例外中列出的組合。不放入不在場景中的人物的圖片。
角色代碼:
A=姜民宇
B=李書妍
情境代碼:
1=笑
2=悲傷
3=憤怒
其他代碼:
BG1=檢疫所走廊
例外: 無 B/3
範例: 角色代碼 A + 情境代碼 1 → `![]({{URL}}/A/1.webp)`

### 元件輸出規則
在符合規則的時刻，把下方標籤原樣以單獨一行輸出。
- `<StatusWindow hp={value} mp={value} />`: 戰鬥開始時與體力變化時。hp = 體力，mp = 魔力。
```

</details>

## 寫好的訣竅

以下不是 MYMI 保證的規則，而是製作作品時有幫助的方法。完成製作後，請用完成畫面的**查看作品**實際聊聊看，一邊調整。想在其他使用者看到之前先測試，可以把**其他設定**的**公開設定**設為**不公開**再完成製作。

- <strong>把資訊和指示分開。</strong>世界觀、人物、隱藏設定當作事實來寫，進行規則則寫成「要做～」這樣的行動，就不容易搞混。
- <strong>為每個人物填寫相同的項目。</strong>為所有人物寫下角色、性格、語氣、關係，即使有很多人物登場，語氣也不會混在一起。
- <strong>用例子說明語氣。</strong>像「不用敬語，句尾拖長」這樣點出特徵，或是寫一句台詞當例子。
- <strong>隱藏設定要連同揭露的條件一起寫。</strong>例如「不主動向使用者透露」、「被問三次以上就坦白」。
- <strong>偶爾才出現的設定移到設定集。</strong>像特定地點、組織這類只有名稱出現時才需要的設定，放在[設定集](/create/lorebook)，提示詞就會變短。
- <strong>需要對話範例的話，寫在作品資訊裡。</strong>沒有另外放範例對話的欄位。

## 遇到問題時

<details>
<summary>顯示「有角色代碼沒有說明。」</summary>

基本型的**圖片輸出規則**中，有代碼沒有寫含義。請把角色代碼、情境代碼、其他代碼的欄位都填好。如果是不會用到的圖片，就到素材分頁刪除。

</details>

<details>
<summary>顯示「提示詞欄位的總字數超過10,000字。」</summary>

基本型會把作品資訊、代碼含義、例外、元件規則中寫的文字全部加起來計算。不常用到的設定，請試著移到[設定集](/create/lorebook)。

</details>

<details>
<summary>AI 不放圖片</summary>

如果是自行撰寫，請確認是否已把**圖片輸出規則**寫進提示詞。如果是基本型，請確認每個代碼都有含義、素材分頁的圖片都已完成。即使如此，偶爾還是可能漏掉，因為 AI 每次的回覆都不一樣。

</details>
